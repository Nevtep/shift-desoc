## Objective
The Manager deploy wizard lets the admin choose the post-deploy authority mode for a fresh Base Sepolia community — **Admin-managed** or **Governance-managed** — runs the matching finalization branch, and the final verification proves the *selected* outcome with explicit positive and negative role checks. The community overview reports the same mode the wizard verified.

## Problem
Docs of record already describe a mode-selecting `FINALIZE_AUTHORITY_MODE` step; the code does not implement it. The wizard hard-codes the Governance-managed handoff and has no mode concept, no mode-aware verification, and no mode label in the overview.

## Specs
- **S1 (contract of record)**: One evidence-backed authority-mode definition across `docs/EN/**`, `.github/project-management/IMPLEMENTATION_STATUS.md`, `scripts/verify-handoff-admin-role.ts` header and `apps/web/lib/deploy/**`: sequence `PRECHECKS → DEPLOY_STACK → CONFIGURE_ACCESS_PERMISSIONS → FINALIZE_AUTHORITY_MODE → VERIFY_DEPLOYMENT`; Admin-managed = deployer keeps ADMIN, timelock does not hold ADMIN, bootstrap coordinator revoked; Governance-managed = timelock holds ADMIN, deployer and bootstrap coordinator do not.
- **S2 (selection)**: The wizard config flow asks for an authority mode (`admin_managed` | `governance_managed`) before create; it is part of `CommunityDeploymentConfig`, validated (required, one of two values), shown in the review step, persisted in `session.deploymentConfig`.
- **S3 (state machine)**: `StepKey` replaces `HANDOFF_ADMIN_TO_TIMELOCK` with `FINALIZE_AUTHORITY_MODE`; step name/purpose and `expectedTxCount` reflect the selected mode (Governance: grant timelock + revoke deployer [+ revoke coordinator]; Admin: revoke coordinator only when present, 0 handoff txs otherwise).
- **S4 (Governance branch)**: Behavior of today's `executeHandoffAdminToTimelock` is preserved exactly (grant timelock ADMIN, revoke coordinator, revoke deployer, same failure messages).
- **S5 (Admin branch)**: Deployer keeps ADMIN; no grant to timelock; bootstrap coordinator ADMIN revoked if held; step fails if deployer lacks ADMIN or timelock holds ADMIN afterward (fail closed, explicit message).
- **S6 (mode-aware verification)**: `VERIFY_DEPLOYMENT` takes the selected mode and adds explicit checks. Admin-managed: deployer holds ADMIN (positive), timelock does NOT hold ADMIN (negative), bootstrap coordinator does NOT (negative). Governance-managed: timelock holds ADMIN (positive), deployer does NOT (negative), bootstrap coordinator does NOT (negative). The existing 17 checks remain; any failed mode check blocks completion (`allVerificationChecksPassed`). Results show the selected mode and each check labelled positive/negative.
- **S7 (resume)**: Interrupting after DEPLOY_STACK (or mid FINALIZE) and resuming runs `FINALIZE_AUTHORITY_MODE` for the *persisted* mode, never the default and never the other mode; the mode cannot be changed on resume. Legacy sessions (with `HANDOFF_ADMIN_TO_TIMELOCK`) remain rejected as incompatible (existing behavior, test pinned) and start fresh.
- **S8 (overview parity)**: The community overview access section reports the authority mode derived from on-chain ADMIN holders using the same probes as S6 (timelock holds ADMIN → Governance-managed; timelock does not and a non-timelock holder is visible → Admin-managed; unreadable → "unavailable", never a guess). It does not use wizard-local state.
- **S9 (no regression)**: Existing 17 verification checks, preflight, DEPLOY_STACK, CONFIGURE_ACCESS_PERMISSIONS, mock/design-mode flow behave as before; design-mode mock executor supports both modes.
- **S10 (QA, from the issue, must be runnable on Base Sepolia)**:
  1. Run the wizard choosing Admin-managed → verification shows the staging admin still holds restricted roles and the timelock does not.
  2. Run it choosing Governance-managed → verification shows timelock holds roles and the staging admin fails the negative checks.
  3. The community overview reports the same mode the wizard verified.
  4. Interrupt the wizard after deploy → resume lands in the correct branch for the chosen mode.
